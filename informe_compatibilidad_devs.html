Destinatario: Equipo de Desarrollo

Fecha de Análisis: 22 de Mayo de 2026

Objetivo: Evaluar si el estado actual del código fuente del Gestor de Portafolios es compatible con las especificaciones técnicas del servidor de producción http://tis.cs.umss.edu.bo/ para el Sprint 4.

2. Hallazgos Críticos (Acción Requerida)

🚨 Conflicto de Versión de Laravel

El servidor de la universidad soporta un máximo de Laravel 11, pero el proyecto fue inicializado o actualizado a Laravel 12 (según el archivo composer.json). Si se intenta desplegar tal cual, podrían existir problemas de dependencias de Composer o rechazo por parte de los administradores del servidor si su entorno restringe paquetes más allá de la versión 11.

3. Recomendaciones para el Equipo Dev

  • Opción A (Recomendada si el servidor es estricto): Hacer un downgrade del framework en composer.json a "laravel/framework": "^11.0". Dado que Laravel 12 salió recientemente, es muy probable que no se estén usando características exclusivas de la v12 y el downgrade sea transparente. Se debe ejecutar composer update y correr los tests para verificar.
  • Opción B: Solicitar al administrador del servidor de los laboratorios la validación de soporte para Laravel 12, argumentando que PHP 8.2 (el cual ya tienen) es suficiente para correr Laravel 12 (requiere PHP 8.2.2+).
  • Variables de Entorno: Preparar un archivo .env.production asegurándose de establecer APP_ENV=production, APP_DEBUG=false, y las rutas correctas para el servidor web Apache.
